# 2048 ADB Bot

Нативный бот для мобильной игры **2048**. Телефон подключён к компьютеру по USB.
Бот читает доску, считает лучший ход **экспектимаксом** и отправляет обычный
свайп через штатный ввод Android (`input swipe`).

Приложение видит только **обычные жесты пальцем** — нет модификации apk, рута
или оверлея. Между ходами делаются «плавающие» минимальные паузы, а у каждого
свайпа рандомизируются точка старта, длина, угол и длительность — на случай если
игра следит за таймингами ввода.

## Чтение экрана

Скриншоты в этой сборке работают (проверено через scrcpy), поэтому основной путь
— **`source: screencap`**: `adb screencap` отдаёт нормальный кадр, весь цикл идёт
только через ADB, никакого дополнительного железа не нужно.

| `source`    | Чтение доски                     | Когда использовать |
|-------------|----------------------------------|--------------------|
| `screencap` | `adb screencap`                  | **этот случай — по умолчанию** |
| `camera`    | веб-камера + OpenCV              | запасной вариант, если сборка вдруг заблокирует скриншоты (`FLAG_SECURE`, чёрные кадры) |

Проверить, что кадр читается (а не чёрный):
```bash
python main.py --test-capture
```

scrcpy для работы бота запускать не обязательно — он берёт кадры напрямую через
`adb screencap`. Но scrcpy удобно держать открытым, чтобы своими глазами видеть,
что происходит на телефоне.

## Как это работает

```
камера/скриншот ─▶ vision (доска 4×4) ─▶ solver (expectimax) ─▶ humanize ─▶ adb input swipe
      ▲                                                                          │
      └────────────────────── читаем доску заново после каждого хода ◀───────────┘
```

Бот **не** симулирует игру вслепую: каждое решение — по свежему кадру, поэтому
случайные новые плитки всегда учтены (кнопка «отмена хода» не нужна). При game
over жмёт «Нова гра» и играет следующую партию, сохраняя лучший результат.

## Что нужно

1. **Телефон**: включить *Отладка по USB*, подключить кабелем, разрешить отладку.
2. **ADB** (Android platform-tools) в `PATH`. Проверка: `adb devices`.
3. **Python 3.9+** и зависимости: `pip install -r requirements.txt`
4. Для `source: camera` — **веб-камера** (или второй телефон как веб-камера),
   закреплённая над экраном игрового телефона. Нужен пакет `opencv-python`
   (уже в requirements).
5. Для `reader: ocr` — бинарь **tesseract** (`apt install tesseract-ocr`).
   Либо `reader: color` без tesseract (см. калибровку).

## Настройка

### A. Сетка доски (скриншот) — основной путь

Дефолтная геометрия в `config.yaml` рассчитана под экран 1080×2400 (как на твоём
скрине), так что может подойти почти сразу. Проверь:
```bash
python calibrate.py            # сохранит overlay.png с наложенной сеткой
```
Открой `overlay.png`: красные точки должны попадать в центр каждой из 16 клеток,
зелёные квадраты — не вылезать за клетку. Если нет — правь блок `geometry`
(`first_center_x/y`, `pitch_x/y`, `cell_size`). Затем:
```bash
python main.py --dry-run       # печатает распознанную доску, без свайпов
```
Числа должны совпасть с экраном.

### B. Калибровка ввода (нужна всегда)

Свайпы отправляются в **пиксельные координаты экрана телефона**:
- `swipe.center_x/center_y` — центр доски (в пикселях телефона). Если `null`,
  берётся из блока `geometry` — для скриншот-режима этого обычно достаточно.
- `game.new_game_button` — координаты кнопки «Нова гра» в пикселях телефона.

Подсказка: временно включи *Настройки → Для разработчиков → Отображать касания*,
чтобы видеть, куда прилетают свайпы.

### C. Камера — только запасной путь

Нужна лишь если сборка когда-нибудь заблокирует скриншоты. Тогда: `source: camera`,
`python calibrate.py --camera` (кликнуть 4 угла поля), вставить `corners` в
`config.yaml`, проверить `warp_preview.png`.

### Без tesseract: `reader: color`

Цвет фона плитки фиксирован под каждое значение. Выучи палитру один раз:
```bash
python calibrate.py --learn-colors     # печатает средний RGB занятых клеток
```
Впиши RGB в `vision.color_palette`, поставь `vision.reader: color`.

## Режимы (переключаются) 

```bash
python main.py --mode balanced   # быстро и сильно (по умолчанию)
python main.py --mode record     # глубже поиск, аккуратнее паузы → максимальный рекорд
python main.py --mode speed      # мелкий поиск, минимальные паузы → больше игр в минуту
```

Пресеты лежат в `config.yaml → modes` (глубина экспектимакса + профиль пауз) и
накладываются поверх базовых `solver`/`timing`. Можно менять под себя.

## Запуск

```bash
python main.py                   # играть по config.yaml + режим по умолчанию
python main.py --mode record --tries 200
python main.py --seed 7          # воспроизводимый рандом пауз/джиттера
```

Каждую игру печатается максимальная плитка и число ходов, в конце — лучший
результат. Прервать — `Ctrl-C`.

## Проверка движка без телефона

```bash
python -m pytest tests/ -q         # механика, солвер, перспектива камеры
python tests/test_solver.py 20     # 20 полных игр самоигрой + статистика
```
На эталонных прогонах (стандартный спавн 2/4) солвер стабильно доходит до
**2048–4096**.

## Про «незаметность» — честно

- **Обычный ADB** (текущий вариант): для *приложения* свайпы — это обычные
  касания. Разброс таймингов защищает от эвристик «слишком равномерный ритм».
  Для 2048 этого достаточно; античита там нет.
- На уровне *ОС* событие от `adb input` несёт флаг инъекции. Если когда-нибудь
  понадобится «железная» неотличимость: `sendevent` в `/dev/input` (нужен root)
  или аппаратный USB-HID (Arduino/Pi как тачскрин). Для текущей задачи не нужно.

## Структура

```
config.yaml            source/camera/geometry, тайминги, солвер, режимы, кнопки
main.py                точка входа (--mode, --source, --dry-run, --test-capture)
calibrate.py           калибровка сетки/камеры и обучение палитры
src/adb.py             обёртка над adb: screencap / swipe / tap
src/camera.py          камера + перспективная коррекция экрана (для secure-сборки)
src/vision.py          кадр → матрица 4×4 (OCR или по цвету)
src/solver.py          механика 2048 + экспектимакс
src/humanize.py        плавающие паузы и джиттер свайпов
src/bot.py             главный цикл read → think → swipe
tests/                 тесты механики/солвера + тест перспективы камеры
```
